# yulo-chat 一对一视频通话开发计划

第一版让同一个聊天室里的两名在线成员直接发起视频通话。成员可接听、拒绝、挂断，在通话中控制麦克风和摄像头，手机支持切换前后摄像头。浏览器优先尝试 WebRTC 直连，需要中继时使用 Cloudflare Realtime TURN。本地联调也支持通过原有的 coturn 凭证方式接入 TURN 测试服务。

通话入口放在现有的在线成员列表。每个账号在同一房间内最多参与一通呼叫或通话。跨房间呼叫、私聊窗口、通话历史、录制和多人通话留给后续版本评估。媒体在浏览器之间直传或经 TURN 转发。D1 继续承担账号和文字聊天的存储，临时通话状态由房间的 Durable Object 管理。

## 第一阶段 实现定向信令

沿用聊天室 WebSocket 入口和每个房间的 ChatRoom。当前 WebSocket 只向浏览器推送业务事件，收到客户端消息时仅检查凭证是否过期。新增独立的通话处理模块，由 `webSocketMessage` 分发。文字消息继续通过 `/api/messages` 提交。新版前端从 `ready` 获知功能已开启并确认设备接口可用后，再声明支持视频通话。服务端从同一 ChatRoom 中已声明支持、认证有效的连接选择收件人。 [WebSocket 入口](src/routes/chat.ts#L848) · [消息接收](src/room.ts#L215)

信令使用 `type` 和 `action` 两个字段。下表用 `call/invite` 表示 `type` 为 `call`、`action` 为 `invite`。

| 操作 | 信令 | 服务端规则 |
| --- | --- | --- |
| 发起 | `call/invite`，携带目标 `userId` 和 `requestId` | 校验双方，原子占用双方的通话名额并生成 `callId`。只通知目标账号符合条件的标签页。向发起页返回成功、对方不可呼叫或忙线。 |
| 响铃 | `call/accept`、`call/reject`、`call/cancel` | 第一条有效操作决定结果。主叫可取消，被叫可接听或拒绝。接听绑定到胜出的连接，并通知其余标签页停止响铃。 |
| 建立媒体 | `call/media-ready`、`webrtc/offer`、`webrtc/answer`、`webrtc/ice` | 接听成功且双方就绪后，由主叫发 offer，被叫答复。仅向选定的两条连接转发信令。双方用 `call/connected` 报告媒体已连接后进入通话，协商超时则释放名额。 |
| 结束 | `call/hangup`、服务端 `call/ended` | 双方均可挂断。服务端释放名额并通知相关页面，带上挂断、超时、断线或设备失败等原因。前端按同一路径清理通话。 |

- **身份与输入校验。** 发送者取自已认证的 WebSocket 附件。接听后的操作同时匹配 `callId`、账号和服务端分配的连接 ID。绑定连接时单独向每个选定页面签发随机通话凭证，用于申请 TURN 和重连。保留 Origin、登录和禁言限制，拨号及接听时检查当前账号状态，拦截给自己拨号。按类型校验消息和大小，对邀请加账号限流及同一接收者的冷却，对 SDP 和 ICE 单独限制发送频率。
- **并发与幂等。** 用 ChatRoom 的 SQLite 存储原子提交状态转换和双方名额占用。双方同时拨号时保留先获准的邀请，双方页面以服务端事件为准。同一次 `requestId` 重试复用结果，重复接听、取消和挂断安全处理。临时去重结果随期限清理。
- **休眠与超时。** DO Storage 保存 `callId`、两名参与者及各自的连接 ID 和通话凭证摘要、当前阶段与截止时间。WebSocket 附件保存连接身份，供休眠后恢复。每个房间只调度最近一个截止时间的 Alarm，到点处理所有已过期会话并安排下一次。消息处理也检查截止时间，避免 Alarm 延迟时接受过期操作。终止时清理会话和名额。SDP、ICE 与 TURN 凭证排除在历史、持久化状态和日志之外。 [WebSocket 休眠](https://developers.cloudflare.com/durable-objects/best-practices/websockets/) · [SQLite 存储](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/) · [Alarm](https://developers.cloudflare.com/durable-objects/api/alarms/)
- **首轮参数。** 振铃 30 秒，接听后准备设备和协商最多 45 秒，已建立通话的信令重连窗口 15 秒。用本地测试覆盖截止前后的行为，再按试用结果调整。

第一阶段验收用三个测试账号。两个账号完成拨号、接听、拒绝、取消和挂断，第三个账号既收不到信令，也无法用已知 `callId` 操作会话。再用被叫的两个标签页验证只会选中一个接听连接。

## 第二阶段 打通 WebRTC 和 TURN

先用最小测试页面和两个测试账号验证音视频。准备本地媒体并初始化 `RTCPeerConnection` 后，双方发送就绪事件，由主叫发起协商。每通电话按 `callId` 串行处理远端 SDP，缓存提前到达的 ICE 候选，等 `setRemoteDescription` 成功后再添加。分别证明直连和中继能传双向音视频，再接入正式界面。 [WebRTC 规范](https://www.w3.org/TR/webrtc/)

1. **签发临时凭证。** Worker 的 `POST /api/calls/ice-servers` 复用登录校验，并检查 Origin、账号状态、房间及通话参与资格。用页面持有的随机通话凭证确认请求来自选定的参与页。接口独立限流，返回 `iceServers` 和有效期，响应设为 `Cache-Control: no-store`。本地模式使用共享密钥签发凭证，Cloudflare 模式请求托管服务签发一小时凭证。用强制中继实测长通话及凭证过期后发起新通话。 [Cloudflare 凭证签发](https://developers.cloudflare.com/realtime/turn/generate-credentials/)
2. **配置托管 TURN。** 为测试和正式环境分别创建 TURN Key，配置 Worker 的 Key ID 和运行时 Secret，将对应环境的 `RTC_TURN_PROVIDER` 设为 `cloudflare`。查看凭证失败日志和中继出站用量。在同站 HTTPS 预览验证真实服务后，再按房间开启正式功能。 [Worker 配置](README.md#cloudflare-realtime-turn) · [中继网络和端口](https://developers.cloudflare.com/realtime/turn/)
3. **验收传输路径。** 同一 Wi-Fi 先验证直连，并从浏览器诊断确认实际使用了非中继候选。然后让两端都设置 `iceTransportPolicy: 'relay'`，在不同网络上确认实际选中中继候选且双方都有声音和画面。再从客户端阻断 UDP，仅提供 TURN TLS 地址，验证 TCP/TLS 路径。记录连接耗时和服务器进出带宽，按中继实测确定灰度并发规模。 [ICE 候选策略](https://www.w3.org/TR/webrtc/#dom-rtcicetransportpolicy)

## 第三阶段 接入聊天室和处理断线

在成员列表里给同房间的在线成员增加视频按钮。聊天室短代码提供来电提示和通话面板，通话控制放进独立前端模块。`chat.js` 负责传入当前成员、WebSocket 事件和登录状态。来电显示对方用户名及接听、拒绝按钮。通话面板显示远端画面、本机预览、麦克风、摄像头及挂断控制。 [成员列表](../../assets/js/chat.js#L1268) · [聊天室短代码](../../layouts/shortcodes/chat.html)

- **设备权限。** 用户主动点拨号或接听后才请求摄像头和麦克风。请求被拒或设备被占用时给出可操作的提示并释放会话。用户取消后才返回的媒体流也要停止。移动端使用 `playsinline`，远端播放被拦时提供点击播放。关闭摄像头时释放视频轨，恢复或切换摄像头时使用 `replaceTrack`，保持音频通话。
- **续期与信令重连。** 当前 access token 有效期为 30 分钟，续签 Cookie 不会改变旧 WebSocket 的到期时间。服务端把连接到期时间告知当前页面。通话页在到期前走现有刷新流程，再用已认证的新连接发送 `call/resume`。服务端核对账号、房间和页面内存中的通话凭证，原子替换连接绑定。收到确认后，页面关闭旧连接并保留原 PeerConnection 和媒体轨道。旧连接迟到的关闭事件只处理旧绑定。 [凭证有效期](src/config.ts#L16) · [WebSocket 过期处理](src/room.ts#L291)
- **异常结束。** 通话期间用轻量状态检查发现失联与功能停用。已连通状态下，绑定连接断开或过期时，服务端启动重连宽限。短暂断开期间，媒体可以继续播放，页面显示重连状态。回到前台时检查信令与媒体状态，重连超时就结束。振铃或协商期断线时释放会话并提示重拨。媒体短暂断开时给浏览器恢复时间，进入失败状态或超时就提示重拨。刷新、离开页面、切换房间和登出时尽力发送结束信令，本地立即关闭 PeerConnection、停止轨道和计时器。对端在收到事件或检测到断线超时后执行同样的清理。

## 第四阶段 验收与回归

使用隔离的本地或测试环境，浏览器联调时显式把 Hugo 的 API 地址指向该环境。音视频页面使用 localhost 或 HTTPS，跨设备测试用 HTTPS 测试站点。自动化覆盖信令和前端状态，音视频和网络路径使用真实浏览器验收。 [本地开发流程](README.md#本地开发) · [现有测试清单](测试清单.md)

| 验收项 | 通过条件 |
| --- | --- |
| 呼叫与竞争 | 验证拒绝、取消、超时、对方离线及忙线。双标签同时接听、双方互拨、取消与接听竞态都只产生一个结果。结束后立即释放双方的通话名额，重拨仍遵循邀请限流。 |
| 隔离与防骚扰 | 第三账号、另一房间、同账号未接听的标签页均无法读取或注入媒体信令。未登录、过期连接、无效通话凭证及超量请求被拦截。 |
| 休眠与恢复 | ChatRoom 实例内存重置后，唤醒仍能识别参与者并处理超时或挂断。用短期 access token 自动化测试续期，再实测一通超过 30 分钟的通话。信令临时断开后，只有原参与页能在窗口内恢复。 |
| 设备与移动端 | 实测桌面 Chrome、Edge、Safari，以及 Android Chrome、iPhone Safari。检查双向音视频、麦克风和摄像头开关、手机镜头切换、拒绝权限、切后台、刷新和关闭标签页。通话结束后两端都释放设备。 |
| 网络与凭证 | 跑完直连、跨网络、移动数据、强制中继及 UDP 受限场景。中继长通话持续有声有画，强制中继时遇到凭证无效或中继不可用能结束并给出明确提示。 |
| 旧功能 | 运行 `npm run typecheck`，构建 Hugo 后运行 `npm run verify-build`，用本地 Worker 跑 `npm run smoke` 和 `npm run frontend-test`。核对注册、登录、文字消息、撤回、上传、成员名单和在线人数。开关关闭或前后端版本错开时仍可使用文字聊天。 |

## 第五阶段 灰度启用

Worker 的视频通话开关默认关闭，支持按房间启用，同时控制 WebSocket 功能声明、信令和凭证接口。新版前端从服务端获知功能已开启后才展示入口。先在测试环境跑完验收，再选一个房间小范围开放。记录呼叫成功率、连接耗时、失败原因、TURN 中继占比与流量。

遇到通话问题时关闭视频开关。服务端停止接收新呼叫和签发凭证，已通话的页面收到结束通知或在状态检查超时后清理资源。灰度前演练一次关闭流程，用两个账号确认文字消息仍能实时收发。

## 多人通话布局草案

三人及以上通话时，按可用宽度安排主画面和副画面。现有通话支持一对一，多人版需要扩展参与者状态、加入退出流程和媒体连接。

- 竖屏窄屏把副画面并排放在顶部，主画面在下方占满宽度，底部留给通话控件和聊天输入。三人时顶部刚好两格。副画面更多时可采用横向滚动，保留主画面的高度。
- 横屏和桌面宽屏把主画面放在左侧，右侧纵向排列副画面，聊天输入框在主画面正下方，与主画面对齐。
- 点按任一副画面可将它切为主画面，原主画面回到对应格子。旋转屏幕时保留当前主画面的选择。各路视频按摄像头原始比例显示，兼顾 4:3、16:9 和竖拍。

多人版的设备设置、成员格子和控制条可参考 RealtimeKit UI Kit。 [Cloudflare UI Kit 示例](https://examples.realtime.cloudflare.com/)
